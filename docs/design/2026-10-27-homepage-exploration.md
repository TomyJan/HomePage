# 主页重写：设计探索记录

日期：2026-10-27。状态：方向探索，尚未选定最终设计；不是实施规格。

## 第三轮：侧舷细化（当前方案）

用户选择第二轮的第一版“侧舷”，继续细化其排布和交互。本轮仍修改设计草图 `docs/design/prototypes/video-first.html`，没有开始正式框架迁移。

- 左上角沿用原站图标，名称为“荼蘼 TomyJan”；右上角留空。
- 左下角保持四个紧凑导航入口，默认选中并展开首页。不再显示额外的折叠态介绍，也不再提供左右换边和独立收起按钮。点击当前入口可关闭，再点重新展开；不同入口之间交叉淡入淡出并带轻微位移，支持快速连续切换。
- 内容区取消整体卡片背景和边框。首页、文章使用双层文字阴影和局部椭圆渐变衬底，渐变在自身边界达到完全透明；服务、联系只显示子卡片，以阴影和少量半透明底色保证可读性。
- 页脚采用两行：实时“在风雨中度过”计时（保留旧版计算口径）；站点地图、服务探针、运行状态及“备案信息”。备案入口展开三条完整记录及原链接，弹层从内容列开始，始终避开导航列。
- 右下角仅保留播放/暂停、静音/取消静音、隐藏/恢复 UI 三个图标按钮。
- 隐藏 UI 后，品牌、导航、内容和页脚全部隐藏；只保留带黑色渐变的底部工具栏。鼠标移动使工具栏出现并重置计时，停留在底部区域时保持显示；离开后静止 1 秒再渐变隐藏。键盘焦点也可维持工具栏，Esc 可恢复 UI；触屏可点按唤出。
- 加载界面改为与正文匹配的深色，关键界面就绪且至少展示 1200ms 后开始退场；随后以约 520ms 过渡到正文。视频始终异步加载，不作为入场等待条件。默认静音。
- 视频维持单一、独立的元素，栏目和观看模式切换均不修改播放源、播放位置、画面尺寸或用户暂停选择。

验证：脚本语法检查；实际确认默认首页、无外壳内容、栏目切换时两组动画、关闭/重新展开、快速连续切换、完整备案链接；在 320×568 和 390×844 下检查边界与遮挡，并修正备案弹层覆盖导航的问题。观看模式已验证 1 秒后隐藏、移动重置计时、悬停与键盘焦点保持显示、Esc 恢复。暂停、静音切换及切换栏目后暂停位置保留已验证；浏览器错误日志为空。临时视口已恢复。

## 第二轮修正：视频优先

用户反馈：第一轮不够创新；页面内容不能影响视频背景播放和观看；“留白”版遮挡画面过多；“雾光”版文字需要更可靠的可读性处理。

因此撤回第一轮对“雾光”的优先推荐，淘汰大块纸面覆盖视频的“留白”方向。下面的第一轮方案仅作为探索历史保留。

本轮直接提供使用项目现有视频的可交互草图：`docs/design/prototypes/video-first.html`。这是一次性设计试验，不是正式框架重写。

新的设计约束：

- 视频作为独立、持续存在的画面层。切换功能、展开或收起面板、切换设计方向均不替换 video 元素，不修改其 src/currentTime，不暂停播放。
- 不压缩视频容器为侧边栏，不因展开内容改变视频构图，不对整个视频加暗幕、模糊或去色滤镜。
- 默认把功能入口停靠在边缘，内容按需在局部展开。保留首页、服务导航、博客文章、联系和支持入口。
- 裸露在画面上的文字使用双层阴影：一层清晰轮廓、一层柔和投影；简介另加范围受限的径向渐变衬底。详情文字放在紧凑、实底的局部面板上。
- “只看影像”一次收起内容与入口，保留返回按钮；主动暂停、声音和换视频独立控制。仅用户主动换视频时修改播放源。
- 移动端需要单独安排入口与展开区域，不能机械缩小桌面布局。当前提供窄屏适配，后续仍需结合实际设备和视频裁切决定最终形态。

三个新方向：

1. **侧舷 · 边缘抽屉**：四张小功能卡竖向停靠边缘，展开面板紧贴入口。可将整组入口和面板左右换边，避开镜头主体。偏向效率和稳定性。
2. **星轨 · 轨道导航**：功能卡围绕角落的一枚小型星环分布，主画面中央保持开放。内容在另一角落展开。科技感来自空间关系和收放动效，避免全屏粒子和装饰指标。
3. **折叠 · 悬浮控制台**：功能卡组成底部紧凑控制台，选中功能后向上展开有限高度的内容，用完折回。继承原有“个人浮窗”的亲切感，默认展示面积更小。

本轮草图不以静态占位图替代播放效果。顶部的播放时间属于设计比较工具，方便观察交互期间的视频连续性，不属于拟上线页面的产品界面。

本轮验证记录：Node.js 语法检查通过，页面仅存在一个 video 元素。实际浏览器操作中，展开抽屉、左右换边、切换三种方案期间播放时间从 00:15 持续推进至 01:31，没有重置。手动暂停在 04:06 后切换方案并收起面板仍保持暂停，恢复后继续推进；进入/退出只看影像模式正常。另检查了 320px 窄屏下轨道导航与文章面板。这里只验证草图行为，不等同于正式网站的性能、跨浏览器或移动设备验收。

项目为手写 HTML/CSS/JavaScript，无 package.json 和 CI 工作流，使用 jQuery 切换 section。未发现 .codegraph，因此本次未使用 CodeGraph。

核心结构为全屏随机视频、中央约 50em × 30em 浮窗、蓝色左侧导航和右侧内容区。包含自我介绍、WordPress 最新文章、站点服务、联系方式、捐助、一言、建站时长及按域名显示的备案信息。

文章从 `https://blog.tomys.top/wp-json/wp/v2/posts?per_page=10&page=1&_fields=date,title,link` 获取。第一轮草图使用 2026-10-27 读取到的前三条真实文章作为固定预览数据，不进行实时请求。

当前正文先设为 display:none，再由 window.load 显示。它让内容依赖整页 load 的完成。新设计应明确区分“关键界面可用”与“所有外部资源加载完成”。

## 三个候选方向

### 雾光 · 影像门户（当前建议）

全屏低饱和影像，左侧身份介绍、右侧四张功能入口卡。首页/关于我、服务导航、博客文章、联系/支持均有直接入口；卡片点开时右侧展开内容，身份与影像保持稳定。

用灰白、灰绿与细线组织内容。二次元由正式版头像和视频承担，科技感由等宽小标签、对齐与简洁的交互反馈承担。中性不等于把原视频强制灰度，视频的饱和度和遮罩强度应按可读性选择。

优点：功能直达，视频有足够展示空间，同时有明显重写后的新面貌。代价：不同视频亮度变化大，需要稳定的文字衬底；移动端必须改成纵向布局。

### 浮窗 · 经典重构

保留旧版中央浮窗与左右分栏的辨识度。侧栏改成低饱和灰绿，导航改中文，正文重新排版；服务和文章仍用卡片直达。移动端侧栏改为顶栏。

优点：继承性最强，用户熟悉的信息结构明确。代价：内容区较小，文章长度与服务数量增加时更容易拥挤；整体新鲜感低于另外两版。

### 留白 · 影像手记

左侧中性纸面承载介绍、服务卡和文章卡，右侧留一条清楚的影像窗口。通过大字号名字、细分隔线和少量等宽文字形成个人刊物感。

背景视频仍位于页面底层，纸面遮挡其一部分；收起面板可观看完整影像。移动端影像改为下方横幅。

优点：内容最清楚，可读性稳定，适合偏清爽的个人气质。代价：影像不是默认视觉中心，科技感最弱；当前字形与影像比例仍需结合用户反馈调整。

三个方向均为一次性构图与交互草图，不是正式网站。草图背景为 CSS 山景构图示意，未生成或替换正式二次元素材。正式版应使用用户现有视频/头像，或之后明确选择的新素材。草图文案是提案，不代表已确认的个人简介。

## 加载与动效提案

1. 初始 HTML 自带加载壳、系统字体、极少量内联 CSS；无需远端字体、图片或脚本即可显示标识和轻量加载动画。
2. 加载关键 CSS、首屏必需脚本与实际用于首屏的字体。关键字体设置有上限的等待与回退字体，避免字体 CDN 失败导致一直停在加载页；具体等待时限在实施规格中确定。
3. 正文关键资源与布局就绪后，加载壳淡出；正文用约 400–650ms 的透明度/位移动画显现，功能卡按约 40–70ms 的间隔出现。草图的重播只演示这一视觉节奏，不模拟真实网络进度。
4. 视频、文章、一言、统计、非首屏图片与预取资源独立异步加载。视频未就绪显示本地封面/纯色衬底，视频就绪再淡入。封面也不作为退出加载页的条件。
5. 视频默认静音并使用 playsinline。提供暂停、声音、切换视频与收起面板；仅用户操作后尝试有声播放。浏览器拒绝自动播放时保留封面与手动播放入口。
6. 视频持续播放层与内容切换层分开，切换功能卡不重置视频。标签切换约 200–300ms，悬停/按压约 120–180ms。
7. 外部 API 超时显示缓存内容或明确的备用链接，不保留无止境 Loading。文章构建时快照 + 浏览器后台更新是一种候选方案；更新失败仍能显示快照。
8. 系统减少动态效果时缩短/关闭过渡、停用自动视频与位移动画；需要用一套行为覆盖加载、页面和背景。
9. 后台标签页暂停视频，恢复时按用户原先的播放选择决定是否继续，避免覆盖用户手动暂停。

动效的作用是表达加载状态、界面层级和反馈，不建议使用强制滚动劫持、长时间等待或全屏持续粒子效果。

## 技术建议（尚待确认）

首选 Astro + TypeScript，显式静态输出。普通组件由 Astro 构建成 HTML；交互集中在少量客户端模块，只有出现复杂交互需求时再加入框架岛。CSS 使用设计变量与组件样式；此阶段不预先决定引入 Tailwind、React 或 Vue。

该项目以个人展示和服务入口为主，静态生成能保证正文预渲染，同时仍可支持浏览器端的视频、功能切换与动画。纯静态部署不需要 SSR/云函数适配器。

动效先考虑 CSS + Web Animations API；如最终方案确需复杂编排，再评估 Motion/GSAP，不为技术栈清单预先增加依赖。

EdgeOne Makers：预备 edgeone.json 的 installCommand、buildCommand、outputDirectory、redirects、headers；输出目录以实际 Astro 配置为准（通常 dist）。对带内容哈希的资源使用长缓存，HTML 使用可更新的缓存策略。运行时版本在实现时核对 Astro 与平台支持交集，并在 CI 和部署环境中一致固定。

CI 提案：

- PR：锁定依赖安装、格式与静态检查、Astro/TypeScript 检查、生产构建。
- Playwright：功能卡与浏览器前进后退、视频控制、移动端溢出、键盘操作、减少动态效果、API/视频/字体失败时仍能进入主界面。
- 检查 404、旧链接重定向配置、关键元数据及静态产物中没有服务端运行时依赖。
- 资源预算/性能审计以真实生产预览为基础，区分主界面可用与视频下载，阈值在基线测量后确定；不在此阶段虚构性能分数。
- 合并后仅在检查成功时触发生产部署；PR 预览与生产使用不同环境。具体选用 Makers Git 集成或 Actions 部署，在实现规格中明确，避免重复触发两套生产发布。

- 文章首次进入时才请求 WordPress REST API，每页十篇，接近底部继续加载；去重追加，保留加载动画、失败提示、重试及“没有更多了”状态。不把文章请求纳入首屏加载条件。
- 媒体图标缩小至 17px，降低阴影和默认背景强度，视觉边距与页面左侧对应；粗指针仍保留 44px 点击区域。状态切换使用 230ms 的淡入和轻微缩放旋转。
- 隐藏界面模式只保留播放器底部渐变和操作区；移动鼠标恢复、底栏悬停或键盘焦点保持，离开后闲置一秒自动渐隐。Esc 恢复完整界面。
- 深色加载壳先绘制，再发起远端字体与视频请求。最短展示 1200ms，字体等待最多 1800ms；视频不参与入场等待，失败时使用 CSS 背景。正文入场与加载壳衔接。
- MiSans 沿用旧站 `cdn.amoe.cc` 样式入口，失败时回退系统字体，成功后 swap。Umami 沿用旧 website ID，正文入场后异步加载；localhost 预览跳过统计。

### 本轮浏览器实测
